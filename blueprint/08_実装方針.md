# 08. 実装方針 — データ構造・アプリ機構・v1からの移行・品質と測定

> 技術基盤（ビルド不要・静的・`index.html`を開くだけ）は維持する。
> 変えるのは**コンテンツの単位と、学習者が「作る」ための機構**。

---

## 1. 維持するもの／変えるもの

| 層 | 維持 | 変更・追加 |
|---|---|---|
| 配信 | 静的・ビルド不要・`file://`可・script注入 | — |
| 永続化 | localStorage（進捗・復習箱・連続日数） | 成果物・判断ジャーナル・校正記録の保存。**エクスポート/インポート**（JSON）を追加（ブラウザ依存の脆さへの対策） |
| 学習ルート | 10問セット・途中再開・復習箱（SRS）・用語その場解説 | ルートの単位を**章（工程）**へ。セット構成を固定比率へ。混合出題 |
| コンテンツ | 用語集336語、良質な問題・講義素材 | **講義は工程単位で書き直し**、問題は再タグ付け・再編・新型追加、**ケースと演習の新機構** |
| 品質ゲート | SOLV=0・言語混入・4択・lint・e2e | タグ必須・用語4択上限・ルーブリック必須・検算必須を追加。**学習効果の指標**を追加 |

## 3. データ構造

### 3-1. 章と周（curriculum.js）
```js
DOJO.CHAPTERS = [
  { id:'ch00', n:0, name:'入門', q:'この仕事は何か', lectures:['ch00-01',…], case:null, hours:{l1:3,l2:0,l3:0} },
  { id:'ch02', n:2, name:'スクリーニング', q:'進めるか、見送るか', lectures:[…], case:'spine/ch02',
    skills:['A1','B1','G1'], hours:{l1:5,l2:5,l3:4} },
  …
];
DOJO.LAPS = [ {id:1,name:'作れる',role:'アソシエイト'}, {id:2,name:'設計し回せる',role:'VP'}, {id:3,name:'判断し責任を負う',role:'ディレクター'} ];
DOJO.SKILLMAP = { A1:{domain:'A',lap:1,desc:'紙LBO10分…'}, … };   // 03のセル
```

### 3-2. 工程講義（lectures/chNN-MM.js）
```js
DOJO.lecture2({ id:'ch02-03', chapter:'ch02', lap:1, title:'紙LBOで入札上限の目安を出す',
  skills:['A1'], minutes:15,
  sections:{ what:`…`, output:`…`, model:`…`, kata:`…`, pitfalls:`…`, terms:[…], next:{exercises:[…], case:'spine/ch02#task2'} }
});
```
固定7節をオブジェクトのキーで強制（欠落はlint error）。

### 3-3. 問題（quiz/）— 型ごとのスキーマ
```js
// 共通メタ
{ id, type:1..14, chapter:'ch04', lap:1, skills:['B1'], archetype:['succession'], risk:['revenue-quality'],
  case:'spine/ch04'|null, source:'v1:fdd-a#17'|null }
// 型11 紙計算:      { q, answer:{value:2.1, tol:0.05, unit:'x'}, exp(検算必須) }
// 型13/14 4択:      { q, choices:[4], a:0, exp }  // SOLV=0維持
// 型3 並べ替え:      { q, items:[5], expertOrder:[…], rationale:[…] }
// 型2 確信度更新:    { vignette, hypothesis, newFact, scale:[-2..2], expertDist:{-2:0,-1:1,0:2,1:5,2:8}, exp }
// 型4 モデル誤り:    { model:{rows…}, bugs:[{where, fix, why}], distractors:[…] }
// 型5 最初の数字:    { summary, candidates:[5], best, why }
// 型6/7/12 生成型:   { prompt, rubric:'rub-ic-question', exemplar:{band:'VP', text}, bands:{analyst:…, associate:…, vp:…} }
// 型8 基準率:        { claim, ask:'確率を%で', baseRate:0.12, source, calibration:true }
// 型9 リターン分解:  { entry:{…}, exit:{…}, answer:{ebitda:…, multiple:…, delever:…}, tol }
```

### 3-4. ケース（cases/spine/chNN.js）
```js
DOJO.caseChapter({ id:'spine/ch04', chapter:'ch04',
  situation:{ docs:[{type:'IM抜粋', body:`…`}, {type:'Q&A回答', body:`…`}] },
  tasks:[ { id:'task1', lap:1, role:'アソシエイト', deliverable:'DD論点リスト', template:`…`, rubric:'rub-dd-issues', skills:['B1','B2'] }, … ],
  lectures:['ch04-01','ch04-02'],
  pro:{ deliverable:`…`, thinking:`…` },        // プロの成果物と思考過程
  calibration:{ ask:'この案件を最終的に推薦する確率', when:'before' },
  newInfo:[ { fact:`上位顧客の契約更改が14か月後`, scItem:'sc-ch04-01' } ],
  trap:['補助金アドバック'], openIssue:['社長の続投期間']
});
```

### 3-5. ルーブリック（rubrics/）
```js
DOJO.rubric({ id:'rub-ic-memo', total:100, passBand:{vp:80, associate:60},
  criteria:[ { name:'推薦と条件', pts:10, bands:{analyst:'…', associate:'…', vp:'…'} }, … ],
  deductions:[ {cond:'仮説が説明になっている', pts:-5}, … ] });
```

### 3-6. 学習者の記録（localStorage → JSONエクスポート可）

## 4. アプリ機構（追加分）

| 機構 | 内容 |
|---|---|
| **章ビュー** | 工程講義→演習→ケース章→ジャーナルを一本の縦スクロールで。次にやることが常に一つ |
| **成果物エディタ** | テンプレ付きテキスト領域（メモ・リスト・表）。数値成果物は簡易表入力（S&U・デットスケジュール・リターン）で**自動検算**（バランス・許容範囲） |
| **ルーブリック自己採点** | 観点ごとに3バンドを選ぶ→合計→模範バンドを表示→ギャップを記録 |
| **プロの成果物の開示** | 自己採点を記録するまで開かない（先に見ると訓練にならない） |
| **確信度の記録** | ケースの指定点で「推薦する確率」をスライダー入力。最終章で結果と比較、Brier的な一致度を表示 |
| **判断ジャーナル** | 5項目の定型。蓄積から「自分の失敗チェックリスト」を自動生成（学びの行を集約） |
| **新型問題のUI** | 並べ替え（ドラッグ or 番号入力）、確信度更新（−2〜+2）、モデル誤り発見（行をタップ→修正を選ぶ）、生成型（入力→ルーブリック） |
| **混合出題** | 「今の章」6割＋既習章4割。タグで型比率を固定 |
| **スキルマップ画面** | 03のセルの達成状況を一覧（進捗画面の主役にする） |
| **エクスポート/インポート** | 学習記録のJSONをダウンロード・復元 |

**ビルド不要の原則は維持**。新機構はすべて素のJSで `assets/` に追加。外部ライブラリは入れない（v1と同じ）。

## 5. v1からの移行（migrate-v1.js の仕様）

1. 全4,309問を読み、**機械分類**：型（計算／場面／定義／その他知識）、推定章（トピック→章マップ 04-§10）、推定周（b→1、i→2、a→3、p→場面に応じ1〜3）
2. 自動タグ付けし、`source:'v1:…'` を残す
3. 格下げ判定：定義型・純知識型は `type:14` に。06-§3の上限（500）を超える分は **出題対象外フラグ**（用語集の例文として保持）
4. 手作業キュー出力：「場面を付ければ型13にできる」候補、「章が判定できない」問題、重複候補
5. 配分レポート（06-§3の目標との差）を出す。**新規作成はこの差分を埋める順で行う**

**原則：既存問題の削除はしない。出題対象から外すだけ。**

## 6. 品質ゲート（lint.js v2）

| ゲート | 条件 | 重さ |
|---|---|---|
| SOLV | 正解が最長かつ次長の1.10倍超の4択 = 0 | error |
| 言語混入 | キリル・ハングル・西欧アクセント・簡体字 = 0 | error |
| 4択は4 | 型13・14のchoices.length===4 | error |
| タグ必須 | type / chapter / lap / skills が全問にある | error |
| 講義7節 | lecture2 の7キーが全てある | error |
| 生成型ルーブリック | 型6/7/12・ケース任務に rubric がある | error |
| 計算の検算 | 型9/11の exp に「検算」がある | error |
| ケース章の完全性 | situation / tasks / pro / calibration / newInfo がある | error |
| 用語4択上限 | 型14が出題対象の10%超 | warning |
| 配分 | 06-§3の各区分が目標の±20%以内 | warning |
| 日本語 | 英単語4文字以上は許容リスト外ならwarning | warning |

e2e（2スイート）は維持し、**新UI（成果物エディタ・ルーブリック・並べ替え・確信度）の操作スイート**を追加。

## 7. 学習効果の測定（「質が高い」と言う根拠）

| 指標 | 測り方 | 目標（道場完走時） |
|---|---|---|
| 成果物の合格 | 各章の成果物バンド | 1周目：全章「作った」、2周目：アソシエイト以上、3周目：VP以上 |
| 校正ギャップ | 自己採点バンド−模範バンドの絶対値の移動平均 | 1周目末1.0→3周目末0.3以下 |
| 確信度の校正 | 推薦確率と結果（ケースの結末）の一致 | ケース8本以上でBrier的スコアの改善 |
| 紙計算の速度 | 10分紙LBOの達成（正解＋時間） | 1周目末までに達成 |
| 専門家一致度 | 並べ替え・確信度更新の専門家分布との一致率 | 60%→85% |
| 判断の言語化 | ICの質問・プレモーテム・メモ赤入れのバンド | VPバンド比率50%以上（3周目） |
| 継続 | 連続日数・週あたり時間 | 週10時間×5か月 |

**コミットの測定値行は、問題数ではなくこれらの到達状況（コンテンツ側：章・講義・ケース・ルーブリックの完成度と配分）で書く。**

---

## 8. 作業の進め方（コンテンツ制作の規律）

- **章単位で完成させる**（講義→演習→ケース章→ルーブリック→lint→e2e→commit）。全章の講義だけ先に書く、はしない
- 1章の制作で必ず**自分で成果物を作ってみる**（著者がやれないものは学習者もやれない）
- 問題は講義とケースから生む（06-§9）。問題だけを独立に量産しない
- 毎コミットの測定値：章の完成数／講義数／ケース章数／ルーブリック数／問題配分（06-§3）／SOLV／lint／e2e
